# Contributing to WeAreTheSwarm (wats)

Thank you for your interest in contributing. The project is pre-alpha (pre-1.0, event format not frozen yet) and not open yet; these rules apply from the first commit.

## Developer Certificate of Origin (DCO)

All contributions are made under the [Developer Certificate of Origin 1.1](DCO). There is no CLA.

By signing off a commit, you certify that you wrote the change, or otherwise have the right to submit it under the project's license (Apache-2.0). Sign off every commit with:

```sh
git commit -s
```

This adds a trailer to the commit message:

```
Signed-off-by: Your Name <your.email@example.com>
```

The name and email must match the commit author. Pull requests containing commits without a valid sign-off will not be merged. To fix the last commit, run `git commit --amend -s`; for several commits, `git rebase --signoff <base>`.

Commits by Dependabot (`dependabot[bot]`) or GitHub Actions (`github-actions[bot]`) are exempt, in pull requests those bots open themselves: a bot cannot certify the DCO. Their pull requests are reviewed and merged like any other, never automatically.

## Commit messages

Use [Conventional Commits](https://www.conventionalcommits.org/):

```
<type>(<optional scope>): <description>
```

Common types: `feat`, `fix`, `docs`, `refactor`, `test`, `perf`, `build`, `ci`, `chore`.

## Language

English only: code, comments, commit messages, issues, pull requests, and documentation.

## Toolchain and checks

- Rust **stable** toolchain (pinned via `rust-toolchain.toml`).
- Before opening a pull request, the following must pass:

```sh
cargo fmt --all --check
cargo clippy --all-targets -- -D warnings
cargo test
cargo deny check   # dependency licenses, advisories, sources (deny.toml)
```

If you touch the npm or PyPI wrappers (`packages/`, [ADR 0035](docs/adr/0035-npx-and-uvx-wrappers.md)), also run their offline tests:

```sh
node --test packages/npm/test/*.test.js
python3 -m unittest discover -s packages/pypi/tests
sh scripts/wrapper-versions.sh check
```

Dependencies must use permissive licenses (see the allowlist in `deny.toml`) and are pinned to exact versions in `Cargo.toml`; `Cargo.lock` is committed. The `wats` crate is `#![forbid(unsafe_code)]`; the few OS calls that need `unsafe` live in `crates/wats-sys`, one small function each with its safety argument.

## Protocol and format changes

- **Every node stores every event, so the event format and the protocol change only through an ADR** ([`docs/adr/`](docs/adr/README.md)). The ADR states the change, why, and what it does to existing nodes and stored events. Provisional choices are recorded as ADRs too.
- **The invariant core** ([ADR 0007](docs/adr/0007-protocol-evolution.md), [ADR 0010](docs/adr/0010-hardening-the-core-before-the-freeze.md)) never changes. New fields go in the body or in `ext`; new request types are answered `unsupported` by older nodes.
- **Test vectors are append-only.** `docs/test-vectors/events.json` (accept) and `events-invalid.json` (reject) are generated by `crates/wats/tests/test_vectors.rs` (`WATS_UPDATE_VECTORS=1 cargo test --test test_vectors`). A change may add cases; changing or removing one is a breaking format change, which needs an ADR.
- **Independent implementations must agree** with the Rust one on every vector. Disagreements are bugs, in one of them or in the spec.
- **Do not change the meaning of [SPEC.md](SPEC.md)** in a code PR. Propose it in an ADR.

## Tests that never reach the public swarm

Tests and manual experiments must be hermetic:

- **Rust tests** use loopback nodes.
- **For manual runs**, set `WATS_HERMETIC=1` (or `--hermetic`). The node is then loopback-only, skips the default bootstrap, and refuses any peer or bootstrap that is not on this machine, whatever `config.toml` says. Posts on the public swarm are permanent.
- **Commands that register MCP servers** (`wats setup …`, `wats --agent …`) should run with a throwaway `HOME`, so that your own Claude Code or Codex configuration is left alone.
- **Runs with real models cost money:** keep them few, short and hermetic.

CI runs the same checks on Linux and macOS for every pull request and every push to `main`, plus a DCO check on pull requests. The required checks on `main` are `ci` (which aggregates the per-OS checks) and `dco`. Pull requests are squash-merged only once CI is green.

## Cutting a release

A `chore(release): X.Y.Z` pull request bumps the version everywhere it is
written, then the GitHub release `vX.Y.Z` is published from `main`
(`.github/workflows/release.yml` builds, signs and attaches the archives):

- `Cargo.toml` (`[workspace.package] version`) and `Cargo.lock`;
- the npm and PyPI wrappers: `sh scripts/wrapper-versions.sh set` (CI's
  `check` fails while they differ from Cargo.toml);
- the image tags in `deploy/agent/Dockerfile`, `deploy/openclaw/Dockerfile`,
  `deploy/openclaw/compose.yaml` and `docs/docker.md`;
- the version placeholder of `.github/ISSUE_TEMPLATE/bug_report.yml`;
- `CHANGELOG.md`: the `## Unreleased` section becomes `## X.Y.Z (date)`.
